Часть 1 — Придумай кейс
Название кейса: "Утренний дайджест по сервисам. Сбор информации о состоянии сервисов за ночь с владельцами, определением приоритета и команды".
Компания и проект: ООО "Ромашка". Это небольшой B2B-сервис с парой десяткой сервисов.
Кому помогает: Дежурному инженеру
Проблема: Вручную очень неудобно каждый день проверять состояние каждого из сервисов, поэтому данная модель вместо инженера дежурной группы обходит все системы, анализирует логи, которые может быть не попали на дашборд и делают сводку
Что делает автоматизация?
- Триггер (программа запускается по ручному запуску и каждый день в 05:00 для того чтоб готовый результат уже был к пересменке)
- Шаги: модель получает на входе папку с логами сервисов за ночь, по файлу на сервис и справочник сервис. Эти 2 источника мы подключаем через MCP-сервер. Агент читает лог каждого сервиса, находит ошибки, оценивает приоритет по правилам и определяем команду по справочнику. После чего он сопоставляет со списком сервисов. В конечном итоге дежурный получает файл с сводной информацией. 
- Результат: файл с результатами за ночь
Часть 2 — Что должно быть в реализации
Для того чтоб все работало, нам нужно создать окружение. Оно будет состоять из 2 контейнеров.
1. Ollama (наш сервер, на котором будет жить наша языковая модель. Он будет принимать работы по сети и отвечать текстом)
2. n8n (Это сам конструктор workflow. В нем мы нарисуем цепочку с указанием триггеров, чтение логов через MCP, будет вызывать агенты и сохранять файлы).
